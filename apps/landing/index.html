    How it works

    Three steps, then it's automatic

    1. 01

      Connect a wallet

      Generate a fresh wallet or import an existing key. Every private key is encrypted at rest and only decrypted for the instant it signs.

    2. 02

      Configure a drop

      Point Stryx at a contract. It reads the live public and allow-list stages straight from chain: price, timing, per-wallet limits.

    3. 03

      Stryx mints

      Fire immediately or schedule for the exact moment a stage opens. Every wallet gets its own result, never guessed.

    Security

    Built so a mistake costs less

    Your keys, your limits, and a pause button. Stryx moves at machine speed; the controls keep you in charge.

    • |key⟩

      Keys encrypted at rest

      Every private key Stryx holds is stored encrypted and decrypted only for the instant it signs a transaction you asked for.

      stored ✓ encryptedin use ✓ only while signing
    • ⟨you|wallet⟩

      Your own wallet stays yours

      Connect a browser wallet or your phone and its keys never leave it. You approve each transaction there. Stryx never sees or stores them.

      extension ✓phone wallet ✓
    • ⟨sim|tx⟩

      Simulated before sent

      Transactions are checked first, so a mint that would revert is caught before it costs you gas.

    • Σ ≤ limit

      Daily spend limits

      Set per account and per wallet, on each network. Anything over the limit simply isn't sent.

      0.38 ETH used1.0 ETH limit
    • |pause⟩

      Emergency stop

      Pause sending for one wallet, your whole account, or the entire service, in one move.

      ⏸ sending paused
